    Notifications & OSDs

    This guide details the architecture, screen positioning, and animation dynamics for floating notification toasts and on-screen display (OSD) cards (Volume, Brightness, Music, and Mini Player) in Quickshell running on the Hyprland compositor.

    Design Parameters and Dynamics

    All floating indicators follow a standardized behavioral contract:

    1. Screen Placement: Top of the screen, horizontally centered (anchors.top: true, anchors.horizontalCenter: parent.horizontalCenter).
    2. Top Margin: topMargin: 46 px (reserves a comfortable visual gap beneath Waybar's 36 px height).
    3. Theming: Colors, translucency, and borders are rendered using Matugen Dynamic Palette Tokens (surface_container, outline, on_surface).
    4. Entrance Animation (Downward Slide):
    5. Translates from _slideY: -28 to 0 over 260–280 ms using Easing.OutCubic acceleration.
    6. Fades in opacity from 0 to 1 over 220 ms using Easing.OutQuad.
    7. Queue Dynamics: When a new notification arrives, it occupies the top slot and fluidly pushes older active notifications downward using move: Transition.
    8. Dismissal Animation: Gently moves upward (to: -20) and fades out (opacity: 0) before unmounting from the model.
    9. LayerShell Surface Lifecycle & Input Masking:
    10. Dynamic Loader Lifecycle: The PanelWindow is instantiated via a Loader { active: toastModel.count > 0 }. When no toasts are active, the surface is completely unmapped from the Wayland compositor, eliminating stale layer surfaces.
    11. Targeted Surface Dimensions: Instead of spanning full-screen width, the window specifies implicitWidth: 380 and dynamic height (Math.min(600, toastModel.count * 140 + 60)), anchored only at anchors.top: true so the compositor centers it horizontally.
    12. Layer Top: Placed on WlrLayer.Top (rather than Overlay), preventing pointer grabs and focus disruption on normal desktop windows.
    13. Input Masking: Uses mask: Region { item: toastCol } to restrict mouse interaction strictly to active notification cards. All transparent areas pass clicks through to underlying windows.

    Source Files Map

    Component Source File Responsibility
    Notification Service modules/notifications/NotificationService.qml DBus server claiming org.freedesktop.Notifications, history store, and Waybar count signal sync.
    Toast Window modules/notifications/NotificationToastLayer.qml Top floating window, model prepending (insert(0)), and column move transition.
    Notification Toast Card modules/notifications/NotificationPopup.qml Floating card styling, slide-down appearance, and dismissal animations.
    Collapsible Notification Card modules/controlcenter/ControlCenter.qml Embedded collapsible drawer with Notifications • ( # ) title, 180° rotating toggle chevron, Clear all button, and scrollable card feed.
    Notification Feed Item modules/notifications/NotificationItem.qml Individual notification item styling in the Control Center drawer.
    Volume OSD modules/osd/VolumeOsd.qml Listens to PipeWire sink changes and animates top-center card.
    Brightness OSD modules/osd/BrightnessOsd.qml Listens to brightnessctl and animates top-center card.
    Music Track Toast modules/osd/MusicOsd.qml Automatic top-center popup on MPRIS track transition.
    Mini Music Player modules/osd/MiniPlayer.qml Interactive player triggered via SUPER + M (see Keybindings Catalog).

    Making Future Adjustments

    Adjusting Vertical Distance

    Edit topMargin in the container Item or toastCol: 

    anchors.topMargin: 46 // Increase to push further down, decrease to lift closer to bar

    Changing Animation Speed

    Inside the appearAnim block: 

    NumberAnimation {
    target: osdCard; property: "_slideY"
    from: -28; to: 0; duration: 260; easing.type: Easing.OutCubic
}

    Live Testing

    • Trigger notification: 
      notify-send "Test" "Smooth slide-down animation"
    • Trigger volume OSD: 
      wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%+
    • Battery states: this configuration exposes no battery OSD or IPC test hook, so warning and critical cards cannot be faked from the shell (qs ipc call battery ... returns Target not found). Battery warnings are rendered by Waybar's battery module, which switches to its warning, critical and charging states from live system data (see waybar/config.jsonc).
